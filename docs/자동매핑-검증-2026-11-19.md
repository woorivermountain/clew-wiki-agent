# 기존 보고서 자동 매핑 검증 — 2026-11-19

실제 파일 파싱·PostgreSQL 조회·FastAPI 경로·GPT-5.6 Sol 호출을 연결해 **9개 사례를 실행했고 모두 기대한 최종 상태와 일치**했습니다. 정상 HWPX·PDF·DB 보고서 3건은 위키에 반영됐고, 누락·NULL·주입문·잘못된 기준·부적합 문서 6건은 보류됐습니다. 실공장 보고서의 정확도를 측정한 결과는 아닙니다.

## 구성

1. 서버가 등록된 파일 또는 DB의 보고서 ID·버전과 확정·재사용 승인 정보를 확인합니다.
2. `report_field_mapper`가 공통 8개 필드를 추출합니다. 각 값과 필드별 인용이 원문에 정확히 있어야 합니다.
3. 코드가 설비 등록·인용·개정·전체 블록 해시를 검사하고 기존 `report_admission_reviewer`에 필드별 인용과 원문 전체를 전달합니다.
4. 기존 중복·유사 사건·개정·내용 검증을 통과한 건만 `Report Original`과 `Maintenance Case` 페이지 및 원장을 같은 스냅샷으로 발행합니다. 과거 사건은 일반 설비 절차의 인용에서 제외합니다.

모델은 실제 `gpt-5.6-sol`, 추론 설정 `low`입니다. 로그인한 Codex CLI를 로컬 Chat Completions 호환 릴레이로 연결했고 모델 대역·응답 재생은 사용하지 않았습니다. 같은 모델로 매핑·편입 심사·설비 작성·문장 검토를 실행했습니다. 실제 API 기본 추론 설정과 다를 수 있으므로 운영 비교에서는 설정도 맞춰야 합니다.

원문은 합성 한국어 HWPX·PDF 보고서와 별도 합성 PostgreSQL DB입니다. DB 누락 사례의 `result_text`는 실제 SQL `NULL`입니다. 바이너리 `.hwp`는 기존 오픈소스 테스트 fixture의 사업계획서를 사용해 부적합 문서 보류를 확인했습니다. 기존 factory 행·매뉴얼 HWPX·PDF는 변경하지 않았습니다.

## 사례별 최종 결과

| 사례 | 기대 = 실제 | 호출 수 | 처리 |
|---|---|---:|---|
| 정상 HWPX | `published` | 4 | 원문·사례·근거 발행 |
| HWPX 결과 누락 | `hold` | 1 | 기존 위키 유지 |
| 정상 PDF | `published` | 4 | 원문·사례·근거 발행 |
| PDF 결과 누락 | `hold` | 1 | 기존 위키 유지 |
| 정상 DB 원문 | `published` | 4 | 원문·사례·근거 발행 |
| DB 결과 SQL NULL | `hold` | 1 | 기존 위키 유지 |

| 현행 압력 기준 오기 | `hold` | 2 | 기존 위키 유지 |

실제 모델 호출은 **25회**입니다. 매핑 9회, 편입 심사 4회, 작성 6회, 문장 검토 6회입니다. 사례 처리 19회와 세 위키의 최초 생성 6회를 합한 값이며 모든 응답은 HTTP 200입니다. 정상 한 건은 이 설비 1대 구성에서 매핑·편입 심사·작성·검토 각 1회로 총 4회였습니다.

정상 3건의 공통 필드 8개와 필드별 인용이 모두 원문과 일치했고, 개정·전체 블록 SHA-256을 보존했습니다. 필드별 인용 목록은 독립 편입 검토에도 그대로 전달됩니다. 누락·주입문·부적합 HWP는 매핑 단계에서 보류됐고, 현행 기준 오기는 매핑 이후 편입 심사에서 보류됐습니다.

## 실제 내용 충돌 탐지

보고서의 결과는 현행 정상 토출압력 기준을 5.5–6.5 bar로 기재하지만, 적용일 2026-11-01의 현행 매뉴얼 R2026.11은 6.5–7.5 bar로 규정하며 이전 기준을 대체한다. 별도 이벤트이더라도 현행 필수 기준을 오기한 중대한 충돌이므로 보류한다.

인용 근거: `src-8ae65932cdba390f907e08d5`, `src-06724b2c730eebfefaefa5ce`.

보고서 결과의 `5.5–6.5 bar`는 원문에 실제로 있으므로 문자열 추출 검사는 통과합니다. 이후 심사가 현행 매뉴얼의 `6.5–7.5 bar`와 충돌함을 확인해 발행을 막았습니다. 매핑 성공과 편입 통과가 구분되는 사례입니다.

## 재실행·변경 보존 검증

- 보류 6건 모두 `current` 링크와 현재 스냅샷 모든 파일의 SHA-256이 실행 전후 같았습니다. 원문·사례 위키 페이지도 생성되지 않았습니다.
- 정상 3건의 동일 ID·버전 재요청과 일반 재빌드는 모델을 다시 호출하지 않고 `unchanged`였습니다.
- 승인된 PDF에 바이트 하나를 덧붙여 추출된 내용이 같아도 원본 지문이 바뀌면 `identity_content_conflict`였습니다. 현재본은 유지됐고 테스트 후 원본을 복원했습니다.
- 매뉴얼 개정만 변경해도 저장한 `dependency_digest`와 달라 새 발행을 중단했습니다. 현재본은 유지됐고 테스트 후 설정을 복원했습니다.
- 필드 위조·다른 필드 인용·미등록 근거 ID·NULL·필수 ID 누락·잘못된 설비·검토 중 원본 변경·정상 개정·미승인·직접 수집 우회 등을 포함한 회귀 테스트 **123개 통과**입니다.
- 독립 OKF v0.2 검사기로 최초·최종 스냅샷 6개 모두 검사했고 통과했습니다. 각 최종 위키는 `6 files: 6 ok`입니다.

## 실제 시험에서 수정한 점과 한계

첫 시험에서는 한 블록이 여러 필드를 뒷받침하는데 대표 인용이 제목 하나라는 이유로 정상 HWPX가 보류됐습니다. 필드별로 검증한 모든 인용을 편입 심사 입력에 전달하고 코드에서도 다시 확인하도록 연결을 고쳤습니다. 원문 검사 조건을 완화하지 않았습니다. 초기 실패 기록은 최종 결과와 별도 폴더에 보존했습니다.

결과 누락 PDF에서는 모델이 원문에 존재하는 `condition`과 `event_id`까지 `null`로 반환했습니다. 최종 보류는 정답이지만 개별 필드 추출·누락 진단이 완전히 정확한 것은 아닙니다. 정상 3건의 추출 성공을 전체 양식의 정확도로 일반화하지 않습니다.

바이너리 HWP 시험은 사업계획서의 파싱과 필수 항목 부족 보류입니다. 정상 제조 HWP의 자동 매핑이나 스캔 OCR 정확도를 입증한 시험은 아닙니다. 현재 raw 파일 경로는 OCR 옵션을 제공하지 않으며 빈 추출·입력 초과는 보류합니다.

일반 설비 페이지에는 정확한 압력 범위의 섹션 배치에 대한 별도 조언이 남습니다. 이를 보고서 편입의 사실 오류 탐지나 오차단 수치에 포함하지 않았습니다.

실험 응답에는 API `usage`가 없으므로 토큰 수·추론 토큰·실제 청구 비용을 측정한 결과가 아닙니다. [비용 산정](LLM-비용-산정.md)의 수치는 공식 단가에 별도의 합산 토큰 가정을 적용한 예산입니다.
