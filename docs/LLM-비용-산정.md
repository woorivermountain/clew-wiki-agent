# LLM 비용 산정

2026-11-19 확인 기준입니다. **보고서 한 건을 처리하는 모든 호출의 합계**가 입력 2만·출력 2천 토큰이면 `gpt-5.6-sol` 약 **$0.12**, `gpt-6.2-astra` 약 **$0.24**입니다. 문서 길이·비교 후보·설비 수에 따라 달라지는 예산 가정이며, 이 프로젝트에서 측정한 API 청구액은 아닙니다.

## 단가와 계산 가정

단위는 100만 토큰당 USD입니다. 각 개별 요청이 기본 단가 구간에 있는 Standard 호출을 가정합니다.

| 모델 | 입력 | 캐시 입력 | 출력 | 공식 출처 |
|---|---:|---:|---:|---|
| `gpt-5.6-sol` | $4 | $0.40 | $20 | [모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-sol) |
| `gpt-6.2-astra` | $8 | $0.40 | $40 | [모델 문서](https://developers.openai.com/api/docs/models/gpt-6.2-astra) |

Sol 단가는 **2026-11-30까지의 프로모션**이며 입력 272k 이하 구간 기준입니다. 적용 기간이 지난 견적은 다시 확인해야 합니다. 장문 구간 여부는 보고서 처리 전체의 합산량이 아니라 **각 요청의 입력 길이**로 확인합니다. 출력 과금에는 추론 토큰도 포함되므로 화면에 보이는 답변 길이만으로 계산하면 부족할 수 있습니다. [추론 토큰 과금 설명](https://developers.openai.com/api/docs/guides/reasoning?api-mode=chat) [공식 가격표](https://developers.openai.com/api/docs/pricing), [Sol 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-sol)

아래는 캐시 할인을 적용하지 않은 계산입니다.

`합계 비용 = Σ(각 호출의 입력 토큰 × 입력 단가 + 과금 출력 토큰 × 출력 단가) ÷ 1,000,000`

| 보고서 한 건의 모든 호출 합계 | Sol | Astra |
|---|---:|---:|
| 입력 20,000 / 출력 2,000 토큰 | $0.12 | $0.24 |
| 입력 80,000 / 출력 6,000 토큰 | $0.44 | $0.88 |
| 입력 250,000 / 출력 20,000 토큰 | $1.40 | $2.80 |

예를 들어 **월 1,000건이 모두 가운데 가정과 같다면** $440 / $880입니다. 계산용 환율을 1달러=1,500원으로 놓으면 660,000원 / 1,320,000원입니다. **실환율이 아닙니다.** 재시도·재심사, OCR·추출기·DB·서버 비용, 부가세 및 환전 비용은 별도입니다. Astra의 이 업무 정확도는 아직 비교하지 않았으며 높은 단가가 품질을 보장하지 않습니다.

## 이 프로젝트에서 실제로 확인한 양

기존 정형 보고서 편입의 [합성 평가 기록](보고서-편입-검증-2026-11-19.md)은 설비 2대 기준입니다. 로그인한 Codex CLI를 호환 릴레이로 연결한 모델 실행이며, 별도 API 키로 청구액을 측정한 실험이 아닙니다. 로컬에 별도 보관한 26건의 요청·응답에는 `usage`가 없으므로 실제 입력·과금 출력 토큰, 추론 토큰 및 캐시 적중량을 알 수 없습니다.

다음은 토큰이 아닌 **문자 수 실측**입니다. 입력은 시스템 지시문과 JSON 사용자 메시지의 합계이고 출력은 저장된 응답 본문입니다.

| 처리 | 호출 수 | 입력 문자 | 출력 문자 |
|---|---:|---:|---:|
| 최초 위키 생성 | 5 | 11,547 | 1,058 |
| 정상 신규 보고서 | 6 | 18,512 | 1,082 |
| 별도 사건 보고서 | 6 | 21,934 | 1,434 |
| 새 개정 보고서 | 6 | 23,041 | 1,373 |
| 전체 평가 | 26 | 96,179 | 5,932 |

한국어·영문 지시문·JSON·식별자가 섞여 있어 문자 수를 확정 토큰 수로 환산하지 않습니다. 위의 비용 표는 이 문자 수에서 산출한 실청구액이 아니라 별도로 둔 토큰 가정입니다.

정상 편입의 6회는 **편입 심사 1회 + 전체 위키 작성 3회 + 문장 검토 2회**였습니다. 신규 [자동 매핑](기존-보고서-자동매핑.md)은 필드 추출을 위한 모델 호출이 1회 추가되므로, 같은 작은 구성에서 성공하면 약 7회가 됩니다. 정형 검사 실패·정확한 중복·승인된 같은 버전의 재요청은 모델을 호출하지 않을 수 있고, 의미 중복·내용 모순 보류는 기존 평가에서 각 1회였습니다. 승인 전 보류 요청을 다시 시도하면 다시 호출될 수 있습니다.

## 비용이 커지는 곳과 다음 개선

현재는 보고서 한 건이 수용돼 [원장과 전체 스냅샷 해시](../okf-agent/clew_okf/workflows/compiler.py)가 바뀌면 [모든 설비를 순회](../okf-agent/clew_okf/stages/step_06_publish/bundle.py)하며 다시 작성·검토합니다. 이번에도 변경 대상이 아닌 EQ-02에 매번 3회가 쓰였습니다. [작성기](../okf-agent/clew_okf/stages/step_04_compose/synthesis.py)는 4,000자 단위의 겹치는 발췌를 최대 4개씩 보내므로 긴 문서·설비 증가에 따라 호출도 늘어납니다. 사건 원문을 작성에서 제외해도 검토 근거에는 보존되므로 사례가 쌓이면 검토 입력은 커질 수 있습니다.

[편입 심사](../okf-agent/clew_okf/stages/step_03_admission/admission_review.py)와 [자동 매핑](../okf-agent/clew_okf/stages/step_02_mapping/mapping.py)의 64,000자 한도는 토큰 한도가 아닙니다. 초과하면 호출 없이 보류합니다. 문장 검토의 기본 24,000자 예산 역시 원문 발췌 기준이며 지시문·JSON 메타데이터는 별도입니다. 현재 [모델 어댑터](../okf-agent/clew_okf/providers/llm.py)는 토큰 사용량을 저장하거나 출력 토큰 상한을 지정하지 않습니다.

다음은 **아직 구현하지 않은 개선안**입니다.

- 설비별 원본·프롬프트·모델 해시로 결과를 재사용하고 변경된 설비만 작성·검토합니다.
- 매핑·인용 선택에는 저비용 모델을, 중요한 편입 심사에는 상위 모델을 배치하되 정답 데이터로 정확도를 먼저 비교합니다.
- 실패한 단계만 제한적으로 재시도하고 전체 위키 재실행 횟수를 줄입니다.
- 응답 파싱 직후 모델·단계·보고서·설비 ID와 `usage`의 입력·출력·추론·캐시 토큰, 지연 시간을 기록합니다. 실제 사용량이 쌓인 뒤 건당·월별 예산을 갱신합니다.

[자동 매핑 실험](자동매핑-검증-2026-11-19.md)은 설비 1대의 독립 위키 3개에서 정상 한 건당 4회 호출했습니다. 설비·원본 구성이 달라 앞선 2대 구성의 6회와 단순 비교하지 않습니다. 두 실험 모두 Codex 릴레이의 추론 설정은 `low`였으며 운영 API와 품질·비용을 비교할 때는 모델 외 추론 설정도 일치시켜야 합니다.
