# 에이전트 실행 순서와 코드 위치

`WikiAgent`는 여러 검증 단계를 조합하는 워크플로입니다. 실행 순서대로 `stages/step_01_*`부터 `step_06_*`까지 읽을 수 있습니다. 각 폴더는 구현 책임을 나눈 Python 패키지이며 별도의 서버나 LLM 프로세스가 아닙니다.

## 보고서 한 건의 처리

| 순서 | 폴더 | 책임 | LLM 사용 |
| --- | --- | --- | --- |
| 01 | [step_01_ingest](../okf-agent/clew_okf/stages/step_01_ingest/) | 업로드·텍스트 원본 저장, DB 조회, 문서 추출, 승인 상태·원본 버전 확인 | 없음 |
| 02 | [step_02_mapping](../okf-agent/clew_okf/stages/step_02_mapping/) | 조건·관측·조치·결과와 식별자 매핑, 필드별 정확한 인용·마스터 대조 | 원문 필드 추출 |
| 03 | [step_03_admission](../okf-agent/clew_okf/stages/step_03_admission/) | 설비 연결, 원문 근거, 중복·유사 사건·개정 충돌 검사 | 의미 관계·내용 충돌 심사 |
| 04 | [step_04_compose](../okf-agent/clew_okf/stages/step_04_compose/) | 해당 설비의 현행 근거에서 인용을 골라 위키 초안 작성 | 인용 선택·분류 |
| 05 | [step_05_review](../okf-agent/clew_okf/stages/step_05_review/) | 조건·개정·순서를 대조해 문제 문장에 근거와 메모 표시 | 별도 문장 검토 |
| 06 | [step_06_publish](../okf-agent/clew_okf/stages/step_06_publish/) | OKF Markdown 번들 렌더링, 각주·내부 링크 검사 | 앞 단계 결과 사용 |

`workflows/compiler.py`가 원본 재확인, 출력 잠금과 스냅샷 교체를 조정합니다. `bundle.py`는 페이지를 구성하면서 작성·검토 함수를 호출하므로 단계가 각각 독립 실행 서비스로 분리된 구조는 아닙니다. 이 재구성에서는 검증·작성 로직을 유지하고 코드 위치와 참조를 정리했습니다.

새 보고서는 신뢰할 수 있는 서버에서 확정·재사용 승인된 뒤 모델 처리로 넘어갑니다. 보고서의 필수 정보가 없거나 근거가 맞지 않으면 보류합니다. 정상적인 JSONB 정본은 02 매핑을 생략하고 03 편입 검사로 연결합니다. 보고서 사례의 조치·결과는 원문과 함께 사례로 보관하며 일반 점검 절차의 작성 입력에서 제외합니다.

문장 검토는 자문 성격입니다. 지적 문장을 자동 삭제·수정하지 않으며 검토 실패·부분 검토 상태도 페이지와 리포트에 표시합니다. 보고서의 편입 통과 여부와 `wiki_reviews`를 구분해 확인합니다. 자동 생성 페이지는 `draft`입니다.

## 단계별 주요 파일

```text
clew_okf/
├── agent.py                          # WikiAgent: run / ingest / map-and-ingest
├── cli.py                            # clew-okf build / check / worker
├── stages/
│   ├── step_01_ingest/
│   │   ├── managed_intake.py          # 원본 저장과 작업 등록을 같은 트랜잭션으로 처리
│   │   ├── documents.py               # kordoc 및 텍스트·CSV 추출
│   │   ├── postgres.py                # 설비·허용 테이블·조회 행 수집
│   │   ├── raw_report_store.py        # 파일·DB·관리형 보고서의 원문 읽기
│   │   ├── report_store.py            # 공통 필드를 갖춘 JSONB 정본 읽기
│   │   └── bootstrap.py               # 초기 DB 스키마·마스터·기존 보고서 탐색
│   ├── step_02_mapping/
│   │   ├── mapping.py                 # LLM 필드 추출 + 코드로 근거 검증
│   │   └── mapped_reports.py          # 매핑 원본·의존 근거가 바뀌었는지 재검증
│   ├── step_03_admission/
│   │   ├── admission.py               # 편입·중복·개정과 발행 조건 조정
│   │   └── admission_review.py        # 별도 LLM 편입 심사
│   ├── step_04_compose/synthesis.py   # 인용 작성과 모델 설정
│   ├── step_05_review/review.py       # 문제 문장 검토
│   └── step_06_publish/bundle.py      # 페이지·목차·출처 렌더링과 검사
├── workflows/compiler.py             # 전체 수집·작성·검증·원자적 게시
├── runtime/
│   ├── service.py                    # 메인 서비스에서 호출할 WikiService
│   ├── jobs.py                       # 영속 작업 큐·lease·복구
│   ├── worker.py                     # 별도 프로세스의 실행·재시도·상태 갱신
│   └── progress.py                   # 진행 이벤트 전달
├── interfaces/
│   ├── api.py                        # 앱 팩토리와 동기 API
│   └── async_api.py                  # 202 접수·업로드·상태 조회 API
├── domain/                           # 설비·보고서·편입 원장 데이터 계약
└── providers/llm.py                   # JsonModel 인터페이스와 모델 호출 어댑터
```

## 어디서부터 읽으면 되는가

1. **메인 서비스 연결**: [runtime/service.py](../okf-agent/clew_okf/runtime/service.py) → [interfaces/async_api.py](../okf-agent/clew_okf/interfaces/async_api.py) → [runtime/worker.py](../okf-agent/clew_okf/runtime/worker.py).
2. **보고서 편입 판단**: [admission.py](../okf-agent/clew_okf/stages/step_03_admission/admission.py)의 `map_and_ingest_report()` → 매핑·편입 검토 → [compiler.py](../okf-agent/clew_okf/workflows/compiler.py)의 준비·게시 함수.
3. **전체 위키 구성**: [agent.py](../okf-agent/clew_okf/agent.py)의 `run()` → `build_wiki()` → 입력 수집 → 번들 작성·검토·검사 → `current` 교체.
4. **모델 교체**: [providers/llm.py](../okf-agent/clew_okf/providers/llm.py)의 `JsonModel`과 [synthesis.py](../okf-agent/clew_okf/stages/step_04_compose/synthesis.py)의 설정 연결.

최초 DB 구성은 일반 보고서와 시작점이 다릅니다. 워커가 `bootstrap.scan_database()`로 허용된 스키마와 마스터를 확인하고 기본 위키를 만듭니다. 명시적으로 매핑한 승인 보고서는 자식 작업으로 등록돼 각각 01~06 검사를 거칩니다. 테이블의 의미나 보고서 컬럼을 임의로 추정해 모든 데이터를 수집하지 않습니다.

## 공개 진입점과 내부 경로

기존 서비스에서 사용하던 아래 import와 명령은 유지합니다.

```python
from clew_okf import WikiAgent, build_wiki
from clew_okf.service import WikiService
from clew_okf.async_api import install_wiki_service
from clew_okf.api import create_app, create_router
from clew_okf.llm import JsonModel
```

루트의 `api.py`, `async_api.py`, `service.py`, `llm.py`는 실제 구현 모듈을 연결하는 호환 진입점입니다. 구현을 수정할 때는 `interfaces/`, `runtime/`, `providers/`를 사용합니다. 기존 `clew_okf.compiler`, `clew_okf.model` 등 내부 경로는 위 새 경로로 옮겼습니다. 테스트의 내부 import·patch 경로도 함께 갱신했습니다.

설치와 실제 서비스 적용은 [리드미](../README.md), [FastAPI 연결](FastAPI-자동편입-초기구성.md), [공장 데이터 준비](실공장-데이터-준비.md)를 참고합니다.
