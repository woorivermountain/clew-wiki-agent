# CLEW 위키 에이전트 변경 기록

## 0.2.0 · 개발 브랜치

### 인터랙티브 위키 작업실

- FastAPI의 위키 접두사 아래에 작업실을 연결했습니다. 기본 경로는 /wiki/studio입니다.
- 원문, 설비 문서, 검토와 승인 상태를 데이터 흐름으로 표시합니다. 노드·참조·각주를 누르면 현재 문서를 유지한 채 하단에서 데이터와 원문을 확인합니다.
- 폴더 탐색, 빠른 문서 찾기, 명령 팔레트, 참조 깊이·필터, 원문 나란히 보기, 비동기 작업의 보류 근거를 지원합니다.

### 표·각주와 적용 조건을 함께 저장

| 변경 이유 | 구현한 내용 |
| --- | --- |
| P6 오일 교환 3,000시간은 매뉴얼 46쪽, 최소 연 1회 각주는 47쪽에 있어 서로 다른 작성 요청으로 전달됐습니다. | `synthesis.structured_evidence`를 추가했습니다. 문서 위치와 정확한 원문 문자열로 연결한 근거 묶음을 모델에 한 번에 전달합니다. |
| 기초 수평도 0.2 mm/m와 적용 조건이 같은 요청에 있어도 모델이 숫자만 골랐습니다. | 모델이 묶음의 일부를 선택하면 CLEW가 해당 묶음의 필수 원문 구절을 전부 렌더링합니다. 각 구절은 원래의 페이지별 각주를 유지합니다. |
| P6에 다른 모델의 노즐 하중 표가 실린 사례가 확인됐습니다. 같은 모델명도 재질별 표에서 수치가 다릅니다. | 지정한 원문 블록을 개별 인용 후보에서 제외하고, 설비별로 검증한 묶음만 제공합니다. 적용 재질이 확인되기 전에는 해당 구간의 묶음을 보류할 수 있습니다. |
| 원문이나 개정이 변경되면 기존에 확인한 구절을 재사용하기 어렵습니다. | 문서 키, 적용 설비, 블록 위치와 인용문을 모델 호출 전에 검사합니다. 구절이 없거나 모호하면 기존 초안과 승인본을 유지합니다. |

빌드 응답에 `selected_groups`를 추가했습니다. 기존 `selected_quotes`는 본문에 기록된 원문 구절 수입니다. 하나의 묶음에 여러 구절이 들어갑니다. 구조화 근거 설정이 없는 경우는 기존 인용 흐름을 사용합니다. Markdown 규격은 OKF 0.2를 유지합니다.

### 필수 근거 묶음 누락 시 발행 보류

- P6 재실행에서 원문에 연결된 묶음이 본문에 통째로 빠지는 경우를 확인했습니다. 묶음마다 `required: true`를 설정하면 해당 설비의 인용 작성 결과에 포함됐는지 코드로 검사합니다.
- 누락된 설비·묶음·원문 위치·구절을 `required_evidence_missing` 결과에 담습니다. CLI와 동기 API는 `hold`, 비동기 작업은 `held`로 기록합니다. 새 스냅샷 발행과 보고서 편입은 보류되고, 기존 초안과 승인본은 계속 사용할 수 있습니다.
- 필수 묶음 검사를 통과한 위키는 검토용 초안으로 게시합니다. 운영 승인 기준과 절차는 [현장용 위키 승인](README.md#현장용-위키-승인)에 정리했습니다.

### 함께 반영한 이전 개선

- **현장용 승인본 조회.** 명시적으로 승인한 스냅샷의 해시가 일치할 때만 `GET /wiki/release`에서 반환합니다.
- **참고문서 범위.** 문서별 `synthesize: false`로 정기점검이나 시나리오 같은 원본을 참고 페이지에 보존하고 작성·검토 입력을 제어합니다.
- **모델 응답 안정성.** JSON 모드와 키 형식 검사, 설정에 따른 병렬 작성·재시도, 확인된 원문 후보 ID로 다시 고르는 경로를 추가했습니다.

### 검증 범위

- 전체 회귀 테스트 227개에서 202개가 통과했고 선택 의존성 또는 통합 환경이 필요한 25개는 건너뛰었습니다. 필수 묶음 검사에는 최초 빌드 보류, 기존 초안·승인본 보존, 보류 후 재실행, CLI와 FastAPI 결과 조회를 포함합니다.
- 단위·통합 테스트에서 각주 누락과 중복, 설비 범위 불일치, 보호한 원문의 제외, 선택된 묶음의 전체 렌더링을 확인했습니다.
- 잘못된 각주 설정에서 작성 모델 호출이 일어나지 않고 기존 초안과 승인본이 보존되는지 확인했습니다.
- 같은 원본 91건과 P1~P6 설정으로 두 버전을 빌드했습니다. 동일한 모의 모델이 시간과 수평 편차만 골랐을 때 새 방식은 연 1회 각주와 설치 조건을 함께 저장했습니다. 적용 재질이 확인되지 않은 노즐 하중 표를 보류했고, 참고 Markdown 91개는 두 결과에서 동일했습니다. P6의 작성 요청은 이 구성에서 27회에서 25회로 바뀌었습니다. 전체 문서의 자동 각주 연결은 추가 검증 대상입니다.
- 같은 P6 원문으로 DeepSeek Flash·Pro, GPT-4.1, GPT-5.6 Sol을 실제 API로 재실행했습니다. 모두 두 필수 묶음을 포함한 초안을 생성했습니다. 이전 GPT-4.1의 실제 응답을 다시 적용한 경우에는 두 묶음 누락과 원문 6구절을 반환하고 기존 스냅샷을 유지했습니다. 실측과 재현은 별도로 기록했습니다.

브랜치는 `codex/structured-evidence-v0.2`입니다. 실행 환경과 설정 예시는 [README](README.md)에 있습니다.
